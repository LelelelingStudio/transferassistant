# 了了了传输助手 · Lelele Transfer Assistant

纯前端、免账号、优先离线的近距离文件传输 + 聊天小工具。打开网页即用，两台设备互传文件不需要经过任何服务器存内容（文件走 WebRTC 点对点，浏览器之间直连）。

```
leleletransferassistant/
├── index.html                 主页面
├── 404.html                   找不到页面时的兜底页
├── manifest.webmanifest       PWA 清单
├── sw.js                      Service Worker（离线缓存）
├── favicon.svg
├── assets/
│   ├── css/app.css
│   ├── js/                    i18n / store / net / scanner / transfer / chat / ui …
│   ├── vendor/                peerjs 1.5.5、qrcode-generator 1.4.4（本地内置，不依赖 CDN）
│   └── icons/                 192 / 512 / 1024 / maskable / apple-touch 图标
└── README.md
```

## 怎么部署

1. 把整个文件夹丢到任意静态托管（GitHub Pages、Cloudflare Pages、Vercel、自己的 Nginx / Caddy 都行）。
0. **部署地址**：`https://transferassistant.leleleling.site/`（把这个目录整份传上去即可）。
1. **必须是 HTTPS 或 localhost**——摄像头/麦克风、Service Worker、剪贴板这些能力在 http 下会被浏览器禁掉。你自己配的域名证书就够用，不需要 Node、不需要数据库。
3. 静态托管记得把 `404.html` 配成自定义错误页。
4. 用手机/电脑浏览器打开后，Safari 用「分享 → 添加到主屏幕」、Chrome 用「安装」，就能当 App 用，断网也能打开。

## 怎么用

- 每台设备的**设备码**是 4 位数字（0000–9999），自动分配、不可手改；如果这个号被别人占了会自动换一个没被占用的。设备名称随时可改。
- **查找设备**：不再逐个号码盲扫。每台设备都同时挂两套信令：一套是自己的正式地址 `lt-xxxx`，另一套是固定的 internal 名册（`ltareg-leleleling-transfer-assistant`）。谁先连上谁当名册节点，其余设备作为成员登记进去，所以点“查找附近设备”其实是向名册要一次在线名单，通常一两秒出结果。名册连不上（比如两端在不同网络、打不通 P2P）时，按钮会变成“强制全表扫描”，这时才会退回 0000–9999 的慢速探测（实测约 12 个号码/秒，整轮 8–15 分钟）。
- **扫码连接**：手机上可以直接调摄像头扫对方的二维码，识别后自动填码并发起连接；扫到的是 `?code=xxxx` 的链接也能认。
- **不可查找模式**：对外仍显示 4 位码，但真实地址变成 `44`+4 位。别人输入你的 4 位码时，程序会自动再试一次 `44xxxx`。扫描不会扫到这类设备。
- **联系人**：加过的设备存 localStorage，之后免二次确认直接传。
- **文件**：多文件同时传，500 KB 分片，可暂停/继续（继续时从最后确认的分片接着发，已收的分片不会重复拼进去）。接收端先落浏览器缓存，传输中会一直提示不要关页面。
- **聊天**：私聊 + 群聊（群号和设备码是两套编号），可拉人、可出二维码。每个人都能当节点，一个人掉线不影响其他人继续传话。
- 语音消息最长 60 秒；聊天记录存 localStorage。

## 已知限制（都是实话）

- **两条链路**：主用 WebRTC 局域网直连；网络差或没网时会提示试蓝牙。但浏览器**不能当蓝牙外设**，两个网页之间无法直接蓝牙互传——蓝牙这条只能走系统分享（`navigator.share`）或连接外部 BLE 硬件（如串口/传感器）。
- **查找 / 连接只对同一局域网 + 同一信令服务有效**。跨网段（光猫和路由器分别拨号、两个子网）互相搜不到，也没法直连；这时名册也登记不上，界面会明确提示“在线名单暂时拿不到”，而不是假装扫完。
- **设备码是自动分配的，不能在界面上改**。启动时如果这个 4 位码已经被别人占了，程序会自动换一个没被占用的，并提示一次。
- **同一台电脑开两个窗口自测不可靠**：本机若开了 Surge / 类似代理的虚拟网卡（198.18.x.x），两端会拿到同一个假 IP，ICE 永远打不通。真实两台设备在同一 WiFi 下才准。
- **没有 TURN 中继**：不在同一局域网时，多数情况下连不上（这是「免费、无服务器」的代价）。
- **Base64 分片**会让实际传输量比文件大约多 1/3；分片大小、并发数在 `assets/js/transfer.js` 顶部可调。
- **localStorage** 存设置/联系人/聊天：清浏览器数据就没了，也不会跨设备同步。
- **群聊是消息转发 mesh**，5–8 人的小群体验最好。
- 默认信令是 PeerJS 公共服务器（`0.peerjs.com`），只用来交换握手信息，不碰文件内容；可在「设置 → 信令服务」里换成自建 PeerServer。

## 换自己的信令（可选）

```bash
npx peerjs --port 9000 --key peerjs --path /
```

在页面「设置 → 信令服务」里填 host / port / path / key，关掉 secure（走 https 时要开），保存后会自动重连。

## 出问题先看这三条

1. 两台设备是不是连的**同一个 WiFi**（不是同一个 WiFi 名字下的两个不同网段）。
2. 是不是有一端开着 VPN / 代理软件（先把代理关掉再试）。
3. 页面右下角「日志」里看人话版错误；底层细节不会直接甩给普通用户。

## 技术栈

原生 HTML / CSS / JS，无构建步骤，无框架。P2P 用 PeerJS（WebRTC DataChannel），二维码用 qrcode-generator，两者都已内置在 `assets/vendor/`，离线可用。深浅色用 `color-scheme` + `light-dark()`，对话框用原生 `<dialog>`，多语言是自建轻量 i18n（中/英）。
